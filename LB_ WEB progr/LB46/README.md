# Лабораторна робота №46: Міні-застосунок «Перемикач теми» на Context API

## Виконані завдання (Рівні 1, 2, 3):
1. **ThemeContext та ThemeProvider:** Створено контекст для глобального управління станом теми.
2. **Хук `useTheme`:** Реалізовано кастомний хук із захистом від використання поза провайдером.
3. **Локальне збереження:** Налаштовано збереження обраної теми у `localStorage`.
4. **Системна тема:** Додано підтримку режиму `system`, який читає налаштування ОС через `window.matchMedia`.
5. **UI та CSS-змінні:** Стилізація виконана через підміну атрибута `data-theme` на тегу `<html>` та використання CSS-змінних. Використано іконки `react-icons`.

---

## Відповіді на контрольні питання:

**1. Чому для теми доцільно використовувати Context, а не передавати props?**
Щоб уникнути "props drilling" (прокидання пропсів через компоненти, яким ці дані не потрібні). Тема — це глобальний стан, який може знадобитися будь-якому компоненту на будь-якому рівні вкладеності.

**2. Що відбудеться з компонентами при зміні теми?**
Усі компоненти, які підписані на `ThemeContext` (викликають `useTheme`), автоматично рендеряться повторно з новими значеннями контексту. Інші компоненти не рендеряться.

**3. Навіщо потрібен useEffect при роботі з localStorage?**
Взаємодія з `localStorage` та `document.documentElement` — це side-effect (побічний ефект), який працює з API браузера. `useEffect` гарантує, що ці операції відбудуться синхронно після того, як React відрендерить DOM, не блокуючи відображення інтерфейсу.

**4. Як працює режим system і куди він звертається при зміні налаштувань ОС?**
Він звертається до CSS-медіазапиту браузера через API `window.matchMedia('(prefers-color-scheme: dark)')`. Ми можемо прочитати поточне значення (`.matches`), а також підписатися на подію `change`, щоб миттєво реагувати на зміну теми в налаштуваннях ОС.

**5. Що дає розділення контексту на два?**
Оптимізацію продуктивності. Якщо розділити `ThemeContext` (зберігає лише рядок теми) та `ThemeDispatchContext` (зберігає лише функцію `setTheme`), то компоненти, які лише перемикають тему (наприклад, кнопка), не будуть рендеритися повторно під час зміни самої теми.

**6. В чому різниця між Context та Zustand для цієї задачі?**
* **Context API** — вбудований інструмент React, вимагає створення Provider, що обгортає компоненти. При зміні значення контексту перемальовує всіх "підписників".
* **Zustand** — зовнішня бібліотека. Вона не вимагає Provider (працює поза деревом React), має менше шаблонного коду та точніше керує рендерами (компонент рендериться лише якщо змінилася конкретна частина стану, на яку він підписаний).

## Примітка щодо локального запуску:
Оскільки проєкт використовується як єдина пісочниця, оригінальний робочий застосунок знаходиться в каталозі `lb33-react`. 
Щоб розгорнути цю лабораторну роботу:
1. Скопіюйте вміст цієї папки у `src/` вашого React-додатка.
2. Виконайте `npm install react-icons`.
3. Запустіть сервер через `npm start`.
